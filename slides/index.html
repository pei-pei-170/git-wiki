很多人把檔案複製到另一個資料夾來管理版本，聰明一點的還會加上日期。

這種做法很簡單，但非常容易出錯：

  • 忘了自己在哪個資料夾
  • 不小心寫到錯的檔案
  • 覆蓋掉不想覆蓋的檔案

有沒有辦法隨時回到任何一個版本，又不會弄亂？

02什麼是版本控制

版本控制是一種記錄一個或一組檔案隨時間變化的系統，讓你之後可以叫回特定的版本。

做這件事的工具叫做版本控制系統（Version Control System，簡稱 VCS）。不只程式碼，電腦上幾乎任何類型的檔案都可以做版本控制。

可以做到什麼？

  • 把檔案或整個專案回復到先前的狀態
  • 比較檔案隨時間的變化
  • 查出是誰在什麼時候改了什麼
  • 把東西弄壞或檔案遺失時，可以輕鬆救回來

集中式

所有版本放在一台伺服器上。伺服器壞了，大家都不能工作，這叫單點故障。

分散式

每個人都完整複製一份，包含完整的歷史，每一份 clone 都是完整的備份。

clone：從別處複製一份完整的專案，第 6 張會再說明。

資料來源：concepts/version-control.mdsources/S01-progit-version-control-and-what-is-git.md

03Git 是什麼

Git 是一種分散式版本控制系統。

commit（提交）：把專案目前的狀態存起來，成為一個快照，就像替所有檔案拍一張照片。

📸 存的是快照

每次 commit，Git 會把所有檔案當下的樣子拍成一張快照。沒有變更的檔案不會再存一次，只存一個連結。

💻 大部分在本地

大部分操作只需要你電腦上的檔案。沒有網路也能 commit，等有網路時再上傳。

🛟 很難遺失

快照一旦 commit 進 Git，就很難遺失。

資料來源：concepts/git.mdsources/S01-progit-version-control-and-what-is-git.md

04開始之前：設定身分與預設分支

課前準備：已安裝 Git、已註冊 GitHub 帳號

以下指令都在終端機輸入。Windows 請開啟 Git Bash 輸入指令。

git config --global user.name "John Doe"
git config --global user.email johndoe@example.com
git config --global init.defaultBranch main
git config --list
  • 名字與 email：把範例中的 John Doe 與 email 換成你自己的。每個 commit 都會永久記錄這兩項，所以第一次 commit 前就要設定好。加上 --global 只要設定一次。
  • 預設分支名稱：讓之後建立的 repository（儲存庫，第 6 張說明）預設分支叫 main，和 GitHub 新 repository 的預設一致。GitHub 自 2020 年中起，新 repository 的預設分支名稱是 main。設定預設分支需要 Git 2.28 以上。
  • 確認設定：用 git config --list 或 git config user.name 查看。

main 是這個專案預設的分支名稱，本簡報不教分支，只要記得名稱要和 GitHub 一致即可。

工作目錄

你使用、修改檔案的地方

已修改
git add→

暫存區

記錄下一次 commit 要包含哪些內容

Git 目錄

Git 存放專案資料的地方

已提交
  • 已修改：檔案改過了，但還沒 commit。
  • 已暫存：標記好，要放進下一次 commit。
  • 已提交：資料已經安全地存進本地資料庫。

已追蹤與未追蹤：新檔案一開始是未追蹤的，在你用 git add 之前，Git 不會把它放進 commit。

循環：編輯 → 暫存 → commit，然後不斷重複。

06建立 repository：git init

repository（儲存庫）：Git 用來記錄專案的地方，也就是專案資料夾裡的 .git 子資料夾。

git init

把既有的資料夾變成 repository。本課使用這個方式。

git clone <url>

複製一個現有的 repository，會下載完整的歷史。

先用 cd 進入專案資料夾，再執行 git init（Windows 的路徑寫法如下）：

cd C:/Users/user/my_project
git init

執行後只建立了 .git，這時還沒有任何檔案被追蹤，要先 add 再 commit。

07查看狀態：git status

不確定檔案現在是什麼狀態？先執行 git status。

$ git add *
$ git status
On branch main
Changes to be committed:
  (use "git restore --staged <file>..." to unstage)
	modified:   CONTRIBUTING.md
	renamed:    README.md -> README

輸出改編自 Pro Git（Git 2.23.0 起的輸出），分支名稱依 S03 的設定改為 main。

輸出中的區塊意思
Untracked files未追蹤的新檔案
Changes to be committed已暫存，會進入下一次 commit
Changes not staged for commit已修改，但還沒暫存
nothing to commit, working tree clean沒有任何變更

git status 只列出檔名，不會顯示改了哪幾行。

08加入暫存區：git add

git add README
git add .
  • git add <檔案>：開始追蹤新檔案，或暫存修改過的檔案。
  • git add .：GitHub Docs 用這個指令加入新 repository 中的檔案並暫存，準備第一次 commit。

暫存（stage）：把變更放進暫存區，準備進入下一次 commit。

把 git add 想成「把這份內容加進下一次 commit」，而不是「把檔案加進專案」。

暫存的是執行 git add 那一刻的內容。之後再改，就要再 add 一次。

資料來源：concepts/git-add.mdsources/S02-progit-recording-changes.mdsources/S07-github-adding-locally-hosted-code.md

09提交：git commit -m

git commit -m "First commit"
  • 在 -m 後面直接寫這次的 commit 訊息，不必開啟編輯器。
  • 不加 -m 時會開啟系統預設的編輯器，所以本課一律用 -m。
  • commit 只記錄暫存區的快照，改過但沒有 add 的檔案，不會進入這次 commit。

看懂 commit 的輸出

$ git commit -m "Story 182: fix benchmarks for speed"
[main 463dc4f] Story 182: fix benchmarks for speed
 2 files changed, 2 insertions(+)
 create mode 100644 README

輸出改編自 Pro Git，分支名稱依 S03 的設定改為 main。

main 是 commit 到的分支，463dc4f 是這個 commit 的檢查碼，最後是改了幾個檔案、新增幾行。

10.gitignore：不想被追蹤的檔案

.gitignore 是一個列出檔名規則的檔案，讓 Git 不要自動加入符合規則的檔案，也不要把它們列為未追蹤。

  • 通常用於自動產生的檔案，例如記錄檔，或建置系統產生的檔案。
  • 在開始專案之前就設定好，避免不小心 commit 不想放進 repository 的檔案。

簡單的例子（.gitignore 檔案的內容）

*.[oa]
build/
  • *.[oa]：忽略以 .o 或 .a 結尾的檔案
  • build/：忽略名為 build 的資料夾中所有的檔案

GitHub 提供各種專案與程式語言的 .gitignore 範本，可以當作起點：github.com/github/gitignore

資料來源：concepts/gitignore.mdsources/S02-progit-recording-changes.md

11遠端 repository 與 origin

遠端 repository（remote）：放在網際網路或某個網路上的專案版本，例如 GitHub 上的那一份。

commit 只記錄在你電腦上的副本，要 push（推送）才會把 commit 推送到遠端，分享給別人。

  • origin：clone 時 Git 預設替來源取的遠端名稱。自己新增遠端時用 git remote add origin REMOTE-URL，把 REMOTE-URL 換成 GitHub 上 repository 的完整網址。GitHub Docs 也用 origin 這個名稱。
  • 用 git remote -v 確認遠端的網址：
$ git remote -v
origin	https://github.com/schacon/ticgit (fetch)
origin	https://github.com/schacon/ticgit (push)

12身分驗證：personal access token

GitHub 從 2021 年 8 月 13 日起，不再接受用帳號密碼驗證 Git 操作，要改用以 token 為基礎的驗證方式。

personal access token（PAT）：可以代替密碼的 token。要像對待密碼一樣保管它。

建立 fine-grained token

  1. 如果 email 還沒驗證，先驗證 email。
  2. 點右上角大頭貼 → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token
  3. 填入名稱，設定有效期限。
  4. repository 只選需要的，權限只給最小的（push 需要把 Contents 設成 write）。
  5. 點 Generate token。

PAT 只能用在 HTTPS 的 Git 操作，遠端網址是 SSH 時要改成 HTTPS。

資料來源：concepts/personal-access-token.mdsources/S08-github-personal-access-tokens.mdsources/S09-github-changelog-password-auth-shutdown.md

13實際操作：把專案推上 GitHub

① 本地：建立並 commit

git init
git add .
git commit -m "First commit"

② GitHub：建立 repository

建立新的 repository，不要用 README、license 或 gitignore 初始化。在 Quick Setup 頁面複製網址，用來取代下面的 REMOTE-URL。

③ 連到遠端並推上去

git remote add origin REMOTE-URL
git remote -v
git push origin main

④ 驗證身分

Username: YOUR-USERNAME
Password: YOUR-PERSONAL-ACCESS-TOKEN

Username 輸入使用者名稱，Password 貼上 personal access token。如果沒有出現提示，可能是電腦已經快取了憑證。

14常見錯誤（一）：add 與 commit

add 之後又改了檔案

同一個檔案會同時出現在已暫存與未暫存兩區。直接 commit，進去的是上次 add 的版本。要再 add 一次。

git commit -a 包進不想要的變更

-a 會自動暫存所有已追蹤的檔案，很方便，但有時會把不想要的變更也包進 commit。

不小心 add 了不想 commit 的檔案

用 git restore --staged <file> 取消暫存，檔案的修改還在。

⚠️ 危險：git restore <file>

不加 --staged 時，會丟掉這個檔案的所有修改。除非非常確定，否則不要使用。

資料來源：concepts/git-add.mdconcepts/commit.mdconcepts/git-restore.mdsources/S02-progit-recording-changes.mdsources/S05-progit-undoing-things.md

15常見錯誤（二）：push 到 GitHub

輸入 GitHub 密碼，結果失敗

從 2021 年 8 月起不接受密碼。在 Password 提示貼上 personal access token。

push 被拒絕

沒有寫入權限，或別人先 push 了。需要先取得別人的更新，才能再 push（本課不教合併）。

建立 repository 時勾了 README

要推上本地專案時，為了避免錯誤，不要用 README 初始化，可以 push 之後再加。

⚠️ 不要上傳敏感資訊

不要把密碼、API key 之類的敏感資訊 add、commit 或 push 到遠端。

分支名稱不是 main

例如沒有做第 4 張的設定，Git 預設會用 master（依 Pro Git 線上版，2026-11-22 擷取）。這時要把 git push origin main 中的 main，換成你的預設分支名稱。

16總結

設定→ git init→ git add→ git commit -m→ git remote add origin→ git push origin main
  • commit 過的東西幾乎都能救回來。從來沒有 commit 過的東西一旦遺失，很可能就找不回來了，所以要常 commit。
  • commit 只在本地，push 之後才會出現在 GitHub。
