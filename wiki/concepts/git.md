# Git

> Git 是一種分散式版本控制系統，它把資料視為一連串的快照，而不是每個檔案的差異清單。[S01]

## 白話解釋

Git 的使用介面和 CVS、Subversion、Perforce 等其他版本控制系統相當類似，但儲存與看待資訊的方式非常不同；學 Git 時最好先放下對其他系統的印象，才不會產生細微的混淆。[S01]

### 快照，而不是差異

大多數其他版本控制系統，把資訊存成「每個檔案隨時間的變更清單」，這種方式稱為差異式（delta-based）版本控制。[S01]

Git 則比較像替一個迷你檔案系統拍一連串的快照：每次 commit（儲存專案目前的狀態）時，Git 基本上會把所有檔案當下的樣子拍成一張照片，並儲存指向這張快照的參照。[S01] 為了效率，沒有變更的檔案不會再存一次，只會存一個連到先前相同檔案的連結。[S01]

### 幾乎所有操作都在本地

Git 大部分的操作只需要本地的檔案和資源，通常不需要網路上其他電腦的資訊；因為整個專案歷史就在本地硬碟上，大多數操作幾乎是瞬間完成。[S01]

例如瀏覽專案歷史，或比較某個檔案現在和一個月前的差異，Git 都是直接讀取本地資料庫，不必連到伺服器。[S01] 所以在飛機、火車上，或連不上 VPN 時，你仍然可以 commit 到本地的副本，等有網路時再上傳。[S01]

### 完整性

Git 中所有東西在儲存前都會計算檢查碼（checksum），之後也用這個檢查碼來指稱它，所以任何檔案或目錄的內容被改動，Git 都會知道；資料在傳輸中遺失或檔案損毀，Git 也都偵測得到。[S01]

Git 使用的檢查碼是 SHA-1 雜湊值：一串由 40 個十六進位字元（0～9 與 a～f）組成的字串，依檔案內容或目錄結構計算而來。[S01] Git 資料庫裡的所有東西，都不是用檔名、而是用內容的雜湊值來儲存。[S01]

### 幾乎只新增資料

在 Git 中執行的操作，幾乎都只是「新增」資料到 Git 資料庫，很難讓系統做出無法復原的事，或以任何方式抹除資料。[S01] 和所有版本控制系統一樣，還沒 commit 的變更仍可能遺失或弄亂；但快照一旦 commit 進 Git 就很難遺失，如果定期把資料庫推送（push）到另一個儲存庫就更安全。[S01] 因此可以放心做實驗，不用擔心把東西嚴重弄壞。[S01]

## 指令範例

S01 只示範了 SHA-1 雜湊值的樣子，沒有提供 Git 指令：[S01]

```
24b9da6552252987aa493b52f8696cd6d3b00373
```

## 新手常見誤解

- **「Git 和其他版本控制系統一樣，存的是每次的差異」**：Git 存的是快照，沒有變更的檔案只存連結。[S01]
- **「沒有網路就不能用 Git」**：大部分操作都在本地進行，離線也能 commit，有網路時再上傳。[S01]
- **「用了 Git 還是很容易弄丟資料」**：commit 之後的快照很難遺失；容易遺失的是還沒 commit 的變更。[S01]
